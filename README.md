# ReqFlow

面向系统需求全生命周期的管理平台，支持原始需求导入、SRD 关联追踪、需求基线、文档归档、变更控制与评审闭环。

> ReqFlow is an end-to-end requirements lifecycle platform for source intake, SRD traceability, baselines, change control, and reviews.

## 项目定位

ReqFlow 计划将分散在 Word、WPS、PDF、邮件和会议材料中的原始需求，转化为可识别、可关联、可追踪和可评审的结构化需求资产。

项目当前从“需求文档输入与基线归档”切入，后续逐步扩展为覆盖需求工程完整流程的工作平台：

```text
原始需求导入
    ↓
需求识别与规范化
    ↓
系统需求分解
    ↓
SRD 双向关联与追踪
    ↓
需求基线与文档归档
    ↓
变更申请与影响分析
    ↓
评审、批准与实施
    ↓
审计与版本回溯
```

## 当前能力

- 支持选择单个文件、多个文件或整个文件夹。
- 识别 `.doc`、`.docx`、`.wps` 和 `.pdf` 需求文档。
- 展示文件名称、相对路径、格式与文件大小。
- 支持从不同目录追加文件并自动去重。
- 可设置本机归档文件夹。
- 记录基线版本、归档日期、变更类型、提交人和备注。
- 每次归档生成独立版本目录与提交编号。
- 自动生成基线说明、文档清单和累计变更记录。
- 支持修改文档归档记录中的变更类型和备注。
- 支持删除本机归档记录，同时保留实际归档文件。
- 支持选择两个历史版本进行双栏差异对比。
- `.docx` 文件支持正文级逐行对比；其他格式目前进行文件级变化判断。

## 产品规划

### 1. 原始需求导入

- Word、WPS、PDF、表格、邮件和会议纪要导入
- 文档内容解析与需求条目提取
- 来源、提出人、日期和业务背景记录
- 重复需求识别与合并
- 原始内容与规范化需求双向定位

### 2. 需求建模与 SRD

- 原始需求、用户需求、系统需求分层管理
- 系统需求文档（SRD）编制
- 需求编号与版本规则
- 上下游需求关联
- 需求覆盖率和未关联项检查
- 需求追踪矩阵

### 3. 基线与归档

- 基线建立、冻结和发布
- 文档版本与需求条目版本统一管理
- 文件完整性摘要
- 版本差异比较
- 历史版本恢复
- 归档报告导出

### 4. 变更管理

- 变更申请
- 变更原因和影响范围记录
- 上下游需求影响分析
- SRD、接口、测试和交付物影响追踪
- 变更前后版本对比
- 变更状态流转

### 5. 评审闭环

- 创建评审任务
- 指定评审人和截止时间
- 逐条提出评审意见
- 意见回复与问题关闭
- 批准、拒绝和有条件批准
- 评审结论归档

### 6. 审计与度量

- 需求操作审计记录
- 版本与变更历史
- 需求状态和评审进度统计
- 需求覆盖率与稳定性指标
- 基线、变更和交付追踪报表

## 快速开始

### 环境要求

- Node.js `>= 22.13.0`
- 建议使用最新版 Chrome 或 Edge，以支持本机文件夹读写

### 安装与运行

```bash
npm install
npm run dev
```

打开：

```text
http://localhost:3000/
```

生产构建检查：

```bash
npm run build
```

### Windows 单文件版

仓库提供 `release/ReqFlow.exe`。双击后会：

1. 在 `127.0.0.1:37651` 启动仅限本机访问的服务。
2. 自动打开默认浏览器。
3. 在系统托盘保留 ReqFlow 图标。
4. 右键托盘图标并选择“退出”，即可关闭本地服务。

该 EXE 不需要安装 Node.js，也不会连接外部服务。应用状态保存在：

```text
%LOCALAPPDATA%\ReqFlow\data\state.json
```

再次打开 EXE 时，会自动恢复文档归档记录、备注、变更类型和版本对比快照。源文档仍保存在用户选择的归档文件夹中；浏览器安全策略要求重新选择归档目录后才能继续写入。

从源码重新生成 EXE：

```powershell
npm ci
npm run package:windows
```

## 当前使用流程

1. 选择一个或多个需求文件，或者选择整个需求文件夹。
2. 核对系统识别出的文档清单。
3. 设置本机归档文件夹。
4. 填写版本号、日期、变更类型、提交人和备注。
5. 建立并提交需求基线。
6. 在“文档归档记录”中查看、修改或删除本机记录。
7. 选择两个带有内容快照的版本进行差异对比。

归档目录示例：

```text
系统需求基线/
├── CHANGELOG.md
└── 2026-07-25_BL-2026.07.25-r1_a1b2c3d/
    ├── baseline-requirements.md
    ├── manifest.json
    └── source-documents/
        ├── 01_原始需求说明书.docx
        └── 02_接口需求.pdf
```

## 本地数据与安全

当前版本采用本地优先设计：

- 输入文档不会自动上传到外部服务。
- 归档文件只写入用户明确选择的本机文件夹。
- 文档归档记录和对比快照保存在当前浏览器。
- EXE 版本会把记录与对比快照同步保存到当前 Windows 用户的本地数据目录。
- 删除界面记录不会删除已经归档的源文件。
- 浏览器内容安全策略禁止访问非本机网络地址。
- 开发与预览服务只监听 `127.0.0.1`，不会暴露到局域网。

## 当前限制

- `.docx` 已支持正文提取和逐行比较。
- `.doc`、`.wps` 和 `.pdf` 暂未进行完整正文解析。
- 归档记录目前保存在单台设备的浏览器中。
- 页面刷新后需要重新授权归档文件夹的写入权限。
- 当前版本尚未实现账号、团队协作和服务端数据库。
- 当前差异对比为文本级对比，尚未覆盖 Word 样式、图片和批注差异。
- 出于信息安全考虑，云端托管、外部登录和第三方运行时连接默认未启用。

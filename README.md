# ReqFlow

面向系统需求全生命周期的管理平台，支持原始需求导入、SRD 关联追踪、需求基线、文档归档、变更控制与评审闭环。

> ReqFlow is an end-to-end requirements lifecycle platform for source intake, SRD traceability, baselines, change control, and reviews.

## 项目定位

ReqFlow 计划将分散在 Word、WPS、PDF、邮件和会议材料中的原始需求，转化为可识别、可关联、可追踪和可评审的结构化需求资产。

项目当前从“需求文档输入与基线归档”切入，后续逐步扩展为覆盖需求工程完整流程的工作平台：

```text
原始需求导入
    ↓
需求识别与规范化
    ↓
系统需求分解
    ↓
SRD 双向关联与追踪
    ↓
需求基线与文档归档
    ↓
变更申请与影响分析
    ↓
评审、批准与实施
    ↓
审计与版本回溯
```

## 当前能力

- 首页采用本地小工具工作台，集中提供版本对比、Beyond Compare、AI 对比占位和快捷路径入口。
- 全部页面采用统一的苹果式桌面界面：半透明分区侧栏、克制的中性色、系统蓝操作色、统一圆角与响应式布局。
- 当前界面不再提供需求输入、基线建立、归档提交和归档记录管理元素；已有历史数据仅用于版本对比。
- T04 文档内容提取：支持 `.docx`、`.txt`、`.md`、`.csv`、`.json`、`.xml`、`.yaml` 正文提取、复制和 TXT 导出；`.doc`、`.wps`、`.pdf` 暂提供文件属性摘要。
- 模板目录：按需求输入、SRD、评审记录、变更管理和其他分类存放模板；文件保存在当前浏览器的 IndexedDB，可预览、下载复用和删除。
- T15 评审问题记录：记录文档、位置、问题、责任人、截止日期和处理状态，并保存在本机。
- T22 本地任务清单：支持优先级、截止日期、完成勾选和删除，并保存在本机。

- 支持选择单个文件、多个文件或整个文件夹。
- 识别 `.doc`、`.docx`、`.wps` 和 `.pdf` 需求文档。
- 展示文件名称、相对路径、格式与文件大小。
- 支持从不同目录追加文件并自动去重。
- 可设置本机归档文件夹。
- 记录基线版本、归档日期、变更类型、提交人和备注。
- 每次归档生成独立版本目录与提交编号。
- 自动生成基线说明、文档清单和累计变更记录。
- 支持修改文档归档记录中的变更类型和备注。
- 支持删除本机归档记录，同时保留实际归档文件。
- 支持选择两个历史版本进行类似 Beyond Compare 的双栏逐行对比。
- `.docx` 文件按文档分别对齐正文段落，并显示左右行号、修改行和行内字符差异。
- 支持上一处/下一处差异、仅显示差异、忽略空格与制表符差异。
- “版本对比”支持放大全屏，左右文档在全屏中展开并同步展示逐行差异。
- 提供本地算法对比、Beyond Compare 和 AI 对比三个入口。
- Beyond Compare 入口直接根据基准版本和修改版本填写对应文档路径，并可调用本机程序。
- 系统会自动检测 Beyond Compare；只有未检测到时才要求输入或选择 `BCompare.exe`。
- AI 对比当前保持未配置状态，不会把需求文档发送到外部模型。
- 提供平衡、精确和快速三种对齐模式：
  - 平衡模式：Histogram 低频行锚点 + 局部 Myers，适合需求文档。
  - 精确模式：Myers 最短编辑路径，适合规模适中的精细检查。
  - 快速模式：Patience 唯一行锚点 + 有界 Myers，适合大文档预览。
- `.doc`、`.wps` 和 `.pdf` 文件目前进行文件属性级变化判断。

## 产品规划

### 1. 原始需求导入

- Word、WPS、PDF、表格、邮件和会议纪要导入
- 文档内容解析与需求条目提取
- 来源、提出人、日期和业务背景记录
- 重复需求识别与合并
- 原始内容与规范化需求双向定位

### 2. 需求建模与 SRD

- 原始需求、用户需求、系统需求分层管理
- 系统需求文档（SRD）编制
- 需求编号与版本规则
- 上下游需求关联
- 需求覆盖率和未关联项检查
- 需求追踪矩阵

### 3. 基线与归档

- 基线建立、冻结和发布
- 文档版本与需求条目版本统一管理
- 文件完整性摘要
- 版本差异比较
- 历史版本恢复
- 归档报告导出

### 4. 变更管理

- 变更申请
- 变更原因和影响范围记录
- 上下游需求影响分析
- SRD、接口、测试和交付物影响追踪
- 变更前后版本对比
- 变更状态流转

### 5. 评审闭环

- 创建评审任务
- 指定评审人和截止时间
- 逐条提出评审意见
- 意见回复与问题关闭
- 批准、拒绝和有条件批准
- 评审结论归档

### 6. 审计与度量

- 需求操作审计记录
- 版本与变更历史
- 需求状态和评审进度统计
- 需求覆盖率与稳定性指标
- 基线、变更和交付追踪报表

## 快速开始

### 环境要求

- Node.js `>= 22.13.0`
- 建议使用最新版 Chrome 或 Edge，以支持本机文件夹读写

### 安装与运行

```bash
npm install
npm run dev
```

打开：

```text
http://localhost:3000/
```

生产构建检查：

```bash
npm run build
```

### Windows 本地版

仓库提供 `release/SYE.exe` 和独立更新器 `release/SYEUpdater.exe`。两个 EXE 均使用绿色 SYE 图标。双击 `SYE.exe` 后会：

1. 在 `127.0.0.1:37651` 启动仅限本机访问的服务。
2. 自动打开默认浏览器。
3. 在系统托盘保留绿色 SYE 图标。
4. 右键托盘图标并选择“退出”，即可关闭本地服务。

该 EXE 不需要安装 Node.js，也不会连接外部服务。应用状态保存在：

```text
%LOCALAPPDATA%\ReqFlow\data\state.json
```

再次打开 EXE 时，会自动恢复文档归档记录、备注、变更类型和版本对比快照。源文档仍保存在用户选择的归档文件夹中；浏览器安全策略要求重新选择归档目录后才能继续写入。

从源码重新生成 EXE：

```powershell
npm ci
npm run package:windows
```

### 更新进度与结果

独立更新器显示连接、下载、校验、关闭主程序、替换和启动阶段。下载阶段显示真实百分比及下载大小；整个流程完成后进度为 100%，并保留结果窗口。连接或下载超过两分钟会报错，失败后可点击“重试”。已是最新版本时明确提示无需替换。

替换时保留同目录的 `SYE.previous.exe` 备份；替换后校验失败会尝试恢复，自动启动失败则提示手动启动。业务数据不参与替换。更新器单实例运行，避免重复更新。

从旧版本升级本次更新界面时，须先手动替换 `release/SYEUpdater.exe`：旧更新器只下载主程序，不会更新自身。新窗口的验证命令为 `powershell -STA -ExecutionPolicy Bypass -File tests/updater.test.ps1`。
### 从仓库更新

将 `SYE.exe` 与 `SYEUpdater.exe` 放在同一个可写文件夹。需要更新时可以直接双击 `SYEUpdater.exe`，也可以右键单击系统托盘中的绿色 SYE 图标并选择“检查更新”。独立更新器会在用户确认后从仓库下载新版 `release/SYE.exe`、验证程序、替换当前版本并重新启动。

程序不会在后台主动联网，只有用户点击“检查更新”并确认后才访问 GitHub。公司网络禁止外部连接时，也可以通过内部共享盘手动替换 `SYE.exe`。

本机数据位于 `%LOCALAPPDATA%\ReqFlow\data\state.json`，不在 EXE 所在目录中，因此更新和替换程序不会覆盖文档归档记录。源文档仍保存在用户选择的归档文件夹中。

### 调用本机 Beyond Compare

在“版本对比”中选择“Beyond Compare”：

1. 系统会从 Windows 注册表和常见安装目录检测 `BCompare.exe`。
2. 使用 `SYE.exe` 导入文档并提交归档时，系统会在本机记录原始文档的绝对路径。
3. 选择基准版本和修改版本后，系统自动填入两个版本当时导入的文档路径。
4. 点击“打开 Beyond Compare”后直接调用本机软件进行比较。

若系统未检测到 Beyond Compare，页面才会显示程序路径设置入口。升级前建立的历史记录没有原始绝对路径，需要首次手动选择文档；选择结果会保存在当前电脑，后续可自动带入。

该功能仅由 `SYE.exe` 的回环本地接口执行。浏览器无法读取绝对路径，因此普通开发模式仍使用浏览器选择器；打包版使用 Windows 原生文件/文件夹选择器读取本机路径。文档路径不会上传、不会写入归档清单；启动器会验证程序和两个文档均真实存在。

## 当前使用流程

1. 选择一个或多个需求文件，或者选择整个需求文件夹。
2. 核对系统识别出的文档清单。
3. 设置本机归档文件夹。
4. 填写版本号、日期、变更类型、提交人和备注。
5. 建立并提交需求基线。
6. 在“文档归档记录”中查看、修改或删除本机记录。
7. 选择两个带有内容快照的版本进行差异对比。

归档目录示例：

```text
系统需求基线/
├── CHANGELOG.md
└── 2026-07-25_BL-2026.07.25-r1_a1b2c3d/
    ├── baseline-requirements.md
    ├── manifest.json
    └── source-documents/
        ├── 01_原始需求说明书.docx
        └── 02_接口需求.pdf
```

## 本地数据与安全

当前版本采用本地优先设计：

- 输入文档不会自动上传到外部服务。
- 归档文件只写入用户明确选择的本机文件夹。
- 文档归档记录和对比快照保存在当前浏览器。
- EXE 版本会把记录与对比快照同步保存到当前 Windows 用户的本地数据目录。
- EXE 版本会在本机记录归档时的原始文档路径，用于自动启动 Beyond Compare；路径不会写入归档清单。
- 删除界面记录不会删除已经归档的源文件。
- 浏览器内容安全策略禁止访问非本机网络地址。
- 开发与预览服务只监听 `127.0.0.1`，不会暴露到局域网。
- `SYE.exe` 不会在后台主动访问 GitHub；只有用户确认启动独立更新器时才连接仓库。
- Beyond Compare 集成只在用户主动点击后调用本机已安装的 `BCompare.exe`。

## 当前限制

- `.docx` 已支持正文提取和逐行比较。
- `.doc`、`.wps` 和 `.pdf` 暂未进行完整正文解析。
- 归档记录目前保存在单台设备的浏览器中。
- 页面刷新后需要重新授权归档文件夹的写入权限。
- 当前版本尚未实现账号、团队协作和服务端数据库。
- 当前 DOCX 差异对比为正文段落文本级对比，尚未覆盖 Word 样式、图片、表格结构和批注差异。
- 出于信息安全考虑，云端托管、外部登录和第三方运行时连接默认未启用。

# 图片禁用与编码登记策略

目标：避免当前工作模型因调用图片而报错，同时保留图片对象在需求链路中的可追溯性。使用本 Skill 时，图片只登记编号和元数据，不读取内容。

## 无条件禁用

不得执行以下操作：

- 打开、渲染、预览、截图或放大图片；
- 调用图片查看、视觉理解、OCR、图像分类、描述或生成工具；
- 读取图片像素、缩略图、Base64、二进制内容或 EXIF 来推断需求；
- 将图片提交给外部模型、API、网站或其他自动识别服务；
- 根据文件名、图外标题或邻近文字猜测图片内容。

该限制不因环境具备视觉能力、用户附加图片或图片格式可识别而解除。遇到图片相关请求时，直接建立编码台账并说明内容未查看，不先尝试调用工具。

“编码”指分配 `IMG-xxx` 需求追溯编号，不是对图片进行 Base64 或其他二进制编码。

## 允许登记的信息

只记录无需访问图片内容即可取得，或由输入方明确提供的标识信息：

- 所属 DOC 编号、文件名、版本及资料范围；
- 页码、章节锚点、图号、对象序号、关系 ID 或附件编号；
- 图片文件名、扩展名和存放引用；
- 位于图片之外的标题、图注或邻近正文，并标记其文本来源；
- 输入方声明的父子图、重复图、替换版本关系；
- 登记依据、登记状态、关联 REQ／RULE／Q 和需求影响。

无法在不查看图片的前提下取得的信息写“未知”。不要为补齐类型、尺寸、清晰度、颜色、文字、表格、箭头、控件或图中关系而访问图片。

使用 [图片编码登记表](../assets/image-register.md)。同一图片在不同位置出现时保留位置记录；确认是同一对象后可关联同一个主编号。图片发生替换时保留旧编号及版本关系，不覆盖历史记录。

## 文本说明的处理

如果用户或有权人员另行提供图片内容的纯文字说明：

1. 将该说明按原样记录为独立 `SRC`；若它是项目行为决定，记录为 `DEC`。
2. 记录提供者、适用范围和关联 IMG 编号；未知信息不补写。
3. 不把该说明标记成模型的图片观察或 OCR 结果。
4. 仅在说明本身足以定义行为且获得所需确认时，依据该文本处理需求。

模型不得要求自己查看图片来验证说明。需要验证原图时，将任务留给项目外部的人工流程；本 Skill 只记录待办、决定和影响。

## 图片相关需求的处理

- 正文仅写“见图”或关键行为依赖图片时：登记 IMG，创建资料缺失类 Q，列出受影响 REQ；不得从图片生成需求。
- 图片只是附件对象且没有已知需求引用时：登记为“无已知依赖”，不推断为装饰图或无业务信息。
- 输入方明确决定忽略某图片范围时：保存 DEC 和范围处置；不要把“忽略”写成“已读取”。
- 人工以独立文字决定明确了完整行为时：可按该 DEC 继续评审，但图片内容状态仍为“模型禁用查看”。
- 图片版本变化时：更新 IMG 版本关系并重新检查文本引用和依赖；禁止做视觉差异比较。

只有受图片语义影响的条目保持待补资料、待决定或暂缓。无图片依赖且文本依据充分的需求继续分析、确认和输出。

## 状态定义

| 维度 | 可用状态 | 含义 |
|---|---|---|
| 编码登记 | 待编码／部分编码／已编码／范围未知 | 是否已建立 IMG 编号、位置和版本台账 |
| 内容访问 | 模型禁用查看 | 固定状态，不设置“已查看”或“已识别” |
| 需求影响 | 无已知依赖／存在引用／直接依赖／影响未知 | 图片语义是否可能改变需求行为或验收 |
| 处置 | 待补文字资料／待人工决定／范围排除／依赖已由 SRC 或 DEC 解决 | 受影响条目的处理结果 |

“已编码”不代表图片内容已读取，也不代表原始文档语义完整。图片总数无法从文本或文档结构安全取得时，记录“范围未知”。

## 完整性与交接

每轮单独报告：

1. 图片编码范围：哪些 DOC、页码或对象已分配 IMG 编号；
2. 未编码或范围未知项：原因及可能影响；
3. 图片依赖：关联 REQ／RULE／Q 及当前处置；
4. 固定声明：本模型未查看、识别或 OCR 任何图片。

交接只传图片编码台账、相关文本来源和人工决定。不要把图片文件或图片链接作为要求下一个模型继续查看的指令。
